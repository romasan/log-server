# Log — сервис приёма и визуализации логов

Небольшое веб-приложение для приёма HTTP-запросов с произвольными query-параметрами, их хранения в памяти и отображения в реальном времени через WebSocket.

## Возможности

- **Приём логов** — любой GET-запрос на `/log?ключ=значение&...` фиксируется в логе.
- **Хранение в памяти** — последние **1000** записей (кольцевой буфер, старые записи вытесняются).
- **Веб-интерфейс** — страница показывает последние 100 записей.
- **Реальное время** — новые записи мгновенно появляются на странице по WebSocket.
- **Расширенный формат** — в ответ на `/log` отдаётся JSON со статусом, ID записи и текущим количеством записей.

## Как это работает

### Сервер (`index.js`)

Приложение построено на **Express** с добавленным **WebSocket-сервером** (`ws`) на том же HTTP-порту.

1. **Статические файлы** — Express раздаёт папку `public` (страница просмотра).
2. **Эндпоинт `/log`** — на каждый GET-запрос создаётся запись вида:

   ```json
   {
     "id": "уникальный id",
     "timestamp": "ISO-дата",
     "dateTime": "DD.MM.YYYY HH:MM:SS",
     "ip": "IP-адрес клиента",
     "params": { "ключ": "значение", ... }
   }
   ```

   - `id` генерируется из времени и случайной составляющей;
   - `ip` берётся из заголовка `X-Forwarded-For` (первый адрес) либо из сокета;
   - `params` — все query-параметры запроса.

3. **Буфер** — записи хранятся в массиве. При превышении `MAX_LOGS = 1000` самая старая запись удаляется (`shift()`).
4. **Broadcast** — каждая новая запись рассылается всем подключённым WebSocket-клиентам.
5. **Эндпоинт `/api/logs`** — отдаёт последние 100 записей в формате JSON для первичной загрузки страницы.

### Клиентская часть (`public/index.html`)

Одностраничный интерфейс без фреймворков:

1. При открытии страницы выполняется `fetch('/api/logs')` — загружаются последние 100 записей.
2. Устанавливается WebSocket-соединение с сервером (`ws://` или `wss://` в зависимости от протокола страницы).
3. При получении нового сообщения запись добавляется в конец списка.
4. На странице удерживается не более 100 записей, старые удаляются.
5. Данные экранируются от HTML-инъекций; некорректные WebSocket-сообщения игнорируются.

## API

### `GET /log?ключ=значение`

Регистрирует запись в логе. Параметры не обязательны.

**Ответ:**

```json
{
  "status": "ok",
  "id": "m6u3q9x2k1",
  "count": 42
}
```

Поля:

- `status` — всегда `"ok"`;
- `id` — идентификатор созданной записи;
- `count` — текущее количество записей в буфере.

### `GET /api/logs`

Возвращает последние 100 записей в виде JSON-массива.

### `GET /` (WebSocket)

Устанавливает WebSocket-соединение. Сервер рассылает каждой новой записи JSON-объект (такой же, как хранится в буфере).

## Установка и запуск

```bash
npm install
npm start
```

По умолчанию сервер слушает порт **3000**. Порт можно изменить через переменную окружения `PORT` в файле `.env`:

```
PORT=8080
```

После запуска откройте в браузере: `http://localhost:3000`

## Пример использования

Зарегистрировать запись:

```bash
curl "http://localhost:3000/log?user=ivan&action=login"
```

Ответ:

```json
{
  "status": "ok",
  "id": "m6u3q9x2k1",
  "count": 42
}
```

Запись сразу появится в веб-интерфейсе.
