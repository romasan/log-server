# Инструкции для Cline

Этот файл содержит правила, которым Cline должен следовать при внесении любых изменений в проект.

## Обязанности при изменениях кода

1. **Проверка документации.** Перед внесением изменений в код изучите существующую документацию (`README.md`, `CHANGELOG.md`, `CLAUDE.md`). Убедитесь, что планируемые изменения не противоречат описанной архитектуре, API, поведению или структуре приложения.

2. **Актуализация документации.** После внесения изменений в код проверьте, не нужно ли обновить документацию:
   - если изменилось поведение, API, структура или возможности приложения — обновите `README.md`;
   - если изменений нет или они не влияют на документируемое поведение — оставляйте `README.md` без изменений.

3. **Добавление новых фич.** Любая новая функциональность должна быть отражена в `README.md`: опишите, как она работает, как ей пользоваться, как она вписывается в существующую архитектуру.

4. **Обновление CHANGELOG.md.** Каждое изменение кода (новая фича, исправление бага, рефакторинг, изменение поведения, зависимости, конфигурации) **обязательно** должно быть отражено в `CHANGELOG.md`.
   - **Язык:** CHANGELOG.md ведётся **только на английском языке**.
   - **Формат:** каждая запись — одна строка, начинающаяся с даты в формате `YYYY-MM-DD`, затем — краткое описание изменений.
   - **Длина:** описание не должно превышать **200 символов** (вся строка).
   - Записи добавляются сверху (новые изменения — выше старых). Если за одну дату несколько изменений, они объединяются в одну строку.

   Пример:

   ```markdown
   # Changelog

   ## 2026-08-12
   - 2026-08-12 Added authentication to the /log endpoint.

   ```

5. **Языки документации:**
   - `README.md` — на русском;
   - `CLAUDE.md` — на русском;
   - `CHANGELOG.md` — на английском.

## Что нельзя делать

- Не удаляйте и не переписывайте документацию без необходимости.
- Не вносите изменения в код «молча» — всегда проверяйте и при необходимости обновляйте документацию и CHANGELOG.md.
